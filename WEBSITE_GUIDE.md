# Website Guide

This folder is a Hugo + HugoBlox site for your personal academic/portfolio website. You do not need to understand everything in the project to make it work. In practice, you mainly edit content files and a few configuration files.

## What this project is

- Hugo builds the website from Markdown and YAML files.
- HugoBlox provides the site theme and reusable page blocks.
- Your content is stored in plain text files, so it is easy to edit and move later.

## The only files you usually need to edit

### 1. Your personal profile
- File: data/authors/me.yaml
- Use this to change:
  - your name
  - role/title
  - bio
  - email and links
  - affiliations
  - education, experience, skills, languages, awards
  - ORCID and other IDs

This is the main file for your identity and CV-style information.

### 2. Your homepage
- File: content/_index.md
- Use this to change:
  - the homepage sections
  - the title of the Research Interests / Projects section
  - the Publications and Talks sections
  - the overall landing page layout

### 3. Your experience page
- File: content/experience.md
- Use this to change:
  - the experience page structure
  - sections like skills, awards, languages

### 4. Your projects page
- File: content/projects/_index.md
- Folder: content/projects/
- Use this to change:
  - the projects page title and intro text
  - add or remove project entries

### 5. Your publications, talks, and blog content
- Folders:
  - content/publications/
  - content/events/
  - content/blog/
- Use these to add new content.

### 6. Site navigation and branding
- File: config/_default/menus.yaml
- Use this to change the main menu items.

- File: config/_default/params.yaml
- Use this to change:
  - your site identity and tagline
  - theme appearance basics
  - header/footer options
  - search settings

- File: config/_default/hugo.yaml
- Use this to change core Hugo settings such as base URL and language defaults.

### 7. Static files such as CV or images
- Folder: static/uploads/
- Use this for files that should be publicly accessible, for example:
  - your CV PDF
  - profile images
  - downloadable assets

## What you can safely leave alone (for now)

These are usually generated or advanced files. You do not need to edit them unless you want custom design work.

- public/ — generated website output
- resources/_gen/ — generated Hugo assets
- node_modules/ — installed dependencies
- package.json — only change if you want to add/remove tools
- hugo_stats.json — generated by Hugo
- layouts/ — advanced template overrides
- assets/ — CSS/JS assets for deeper customization

If the site works, leave these alone unless you are intentionally changing the design system.

## Quick start

From this folder, run:

```bash
pnpm install
pnpm dev
```

Then open the local preview URL shown in the terminal.

To build the site for production:

```bash
pnpm build
```

## Recommended editing order

If you want to get your website up quickly, do this in order:

1. Edit data/authors/me.yaml with your personal details.
2. Edit content/_index.md for your homepage content.
3. Edit content/experience.md for your experience page.
4. Add or edit content in content/projects/, content/publications/, and content/events/.
5. Adjust menu links in config/_default/menus.yaml.
6. Adjust appearance in config/_default/params.yaml.
7. Only then consider advanced design changes in assets/ or layouts/.

## What to change for a simple personal website

If you want a clean, basic site and do not care about heavy customization, you only need to edit:

- data/authors/me.yaml
- content/_index.md
- content/experience.md
- content/projects/_index.md
- content/projects/*
- config/_default/menus.yaml
- config/_default/params.yaml

Everything else can stay as-is.

## What to ignore if you just want it to work

If your goal is simply to publish your website, you can mostly ignore:

- layouts/
- assets/
- public/
- resources/_gen/
- hugo_stats.json

Those are either theme internals or generated output.

## Best practice

- Keep your main content in Markdown files.
- Use YAML files for profile and site settings.
- Do not edit generated folders manually.
- Make small changes and preview often.

## In short

Edit:
- your content files in content/
- your profile in data/authors/me.yaml
- your menus and site settings in config/_default/

Leave alone:
- generated folders like public/ and resources/_gen/
- theme internals in layouts/ and assets/ unless you want custom design
